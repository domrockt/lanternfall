## K3 — Optimierung (umgesetzt)

- `SpatialHash`: flaches Zell-Array (256×256 Zellen für `cellSize 32`, Offset −64 →
  Weltbereich 0..4096 plus Rand) statt `Map<number,T[]>`, plus Overflow-Map nur für
  Koordinaten außerhalb; `clear` leert nur benutzte Zellen (`usedIdx`), die Buckets
  bleiben zur Wiederverwendung; Key als Bitpacking statt Multiplikation;
  `floor(x * inv)` statt Division. Keine Allokation pro Frame.
- `ProjectilePool.compact`: Swap-Pop statt `splice` (O(1)-Entfernen, keine Array-Verschiebung).
- **Zellgröße bleibt 32 px**: Mikrobenchmark zeigt 32 als schnellste Größe; 40/48 sind
  bei mehr Kandidaten ähnlich schnell, 16/20/24 langsamer durch mehr Zell-Lookups.
  32 px ≈ 2× größter Gegnerradius (11 px), passt also zum Gegner-Radius. Verhalten
  (Kandidaten und Distanzfilter) unverändert.
- Nachher-Mikrobenchmark (500 Punkte, Cluster r=240, 300 Frames): **0,041 ms/Frame**
  bei `cellSize 32` gegenüber **0,058 ms/Frame** in K2 = **−29 %** Hot-Path-Zeit
  (`shots/m10-perf-500-hash-bench-after.json`).
- `scripts/separation-check.mjs`: `passed: true`, 18 Gegner, 0 Overlaps, minDist 2,54 px.

Nachher-Messung im echten Burst folgt in K5 (gleiche 8-s-Methode + 3× `npm run perf`).
